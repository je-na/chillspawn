# ChillSpawn

[English](README.md) · [Slovenčina](README.sk.md) · [Deutsch](README.de.md) · **Українська** · [Polski](README.pl.md) · [Français](README.fr.md) · [Español](README.es.md) · [Português](README.pt.md)

> Машинний переклад. У разі розбіжностей чинним є [англійський оригінал](README.md).

Серверний мод для DayZ. Гравці вводять `!car` у чат, щоб створити готовий до поїздки червоний «Ольга-24» за шість метрів північніше від них: з колесами, свічкою запалювання, радіатором, зарядженим акумулятором, фарами, дверима, капотом і багажником, повним баком пального, охолоджуючої рідини, масла та гальмівної рідини. Якщо ця точка заблокована або знаходиться у воді, спробує сусідні точки; якщо жодна не вільна, гравцеві пишуть повідомлення про необхідність переміститися, і ця спроба не враховується в ліміт. Отримує приватне повідомлення, що авто зникне протягом 15 хвилин. Кожен гравець може створити одну «Ольгу» кожні 15 хвилин ігрового часу (час підключення до сервера, а не реальний час). Створені автомобілі не отримують пошкоджень, і ніхто всередині не травмується при зіткненні.

Гравці також можуть вводити `!survive` раз на 2 реальні години для отримання невеликого набору виживання. Адміністратори мають необмежений доступ і отримують `!adminkit`.

Клієнтам не потрібен цей мод. Завантажуйте його як `-servermod=@ChillSpawn`. Написано для DayZ 1.30.

> **Статус: протестовано на DayZ 1.30 experimental.** Кожна команда, адміністратори, набори та захист автомобілів працюють на живому сервері без клієнтського мода. Див. [Відомі обмеження / спочатку тестуйте](#відомі-обмеження--спочатку-тестуйте). У файлі [docs/PROMPTING.md](docs/PROMPTING.uk.md) показано, як цей мод був створений.

## Структура папок

```
ChillSpawn/                    -> packs to @ChillSpawn/addons/ChillSpawn.pbo
  config.cpp                   CfgPatches/CfgMods, script modules
  scripts/3_Game/ChillSpawn/   CS_Config (JSON config), CS_PlayerTracker (playtime + rate limit)
  scripts/4_World/ChillSpawn/  CS_Core, CS_Commands, CS_VehicleSpawner, CS_KitSpawner,
                               CS_CarProtection, CS_Messenger
  scripts/5_Mission/ChillSpawn/ MissionServer hooks (chat, connect, disconnect)
config.example.json            the default config, for reference
docs/PROMPTING.md              how this mod was made with Claude, and prompts to make your own
tools/build-linux.sh           builds the PBO on Linux (see Building)
```

## Конфігурація

При першому запуску мод записує `$profile:ChillSpawn/config.json` (папка `-profiles` сервера). Кожна запись у `Presets` та `Kits` стає окремою командою чату, тому власники серверів можуть додавати нові без торкання коду. Типові значення:

| Команда | Створює | Ліміт |
|---|---|---|
| `!car` | Червона Ольга 24, готова до поїздки, без пошкоджень, екіпаж захищений | 1 кожні 15 хв ігрового часу |
| `!ada` | Зелена Ада 4x4, те саме (`OffroadHatchback_Blue` / `_White` для інших кольорів, з відповідними класами `_Blue` / `_White` для дверей, капота та багажника) | 1 кожні 15 хв ігрового часу |
| `!hatchet` | Топор на землі за 1 м | 3 кожні 60 хв ігрового часу |
| `!survive` | У інвентар гравця: банка тушонки, повна пляшка води, таблетки для очищення, бинт і тетрациклін | 1 кожні 2 реальні години |
| `!adminkit` | Тільки адміністратори. На землі перед ними: рюкзак Alice, M14 з 3 повними магазинами на 20 патронів та 3 коробками .308, M4A1 з 3 повними магазинами на 60 патронів та 2 глушниками, повний балістичний жилет, шолом MICH з нічним баченням та батареями, камуфльована куртка TTsKO, штани та черевики, рукавиці та мисливський ніж | немає |

Дві вбудовані команди завжди доступні:

| Команда | Дія |
|---|---|
| `!list` | Перелічує все, що може створити гравець, по одному на рядок, з кількістю залишку та часом до наступної доступності, якщо ліміт вичерпано |
| `!help` | Перелічує команди, доступні гравцеві |

Пресет або набір не можуть називатися `list` або `help`; вбудовані мають пріоритет, а в журналі сервера з'являється попередження.

### Адміністратори

Додайте Steam64 ID адміністраторів у `Admins`:

```json
"Admins": ["76561198000000000"],
```

Адміністратори не мають лімітів і можуть використовувати команди, позначені як `AdminOnly`. Інші гравці не бачать адміністративних команд у `!help` або `!list`, і нічого не станеться, якщо вони введуть таку команду.

### Пресети

Кожен пресет має свій ліміт (одна Ольга та одна Ада кожні 15 хвилин — це окремі дозволи). Щоб додати пресет, скопіюйте блок у `Presets`, надайте йому новий `Command` та перезавантажте сервер. Поля:

| Поле | Значення |
|---|---|
| `Command` | Команда чату без префікса (`car` → `!car`) |
| `DisplayName` | Назва, що відображається в повідомленні |
| `ClassName` | Клас транспортного засобу або предмета для створення |
| `Attachments` | Класи, що кріпляться до нього. Повторіть клас для кожного слоту, який він займає (чотири колеса) |
| `DistanceMetres`, `BearingDegrees` | Місце появи відносно гравця. 0° = північ, 90° = схід |
| `DespawnSeconds` | 0 = ніколи не зникає |
| `MaxSpawns`, `LimitMinutes` | Кожен гравець може створити це `MaxSpawns` разів кожні `LimitMinutes` хвилин ігрового часу |
| `AdminOnly` | Тільки адміністратори можуть використовувати |
| `SpawnMessage` | `%1` = DisplayName, `%2` = хвилини до зникнення |
| `FuelFraction`, `CoolantFraction`, `OilFraction`, `BrakeFluidFraction` | Тільки для транспортних засобів: заповненість кожної рідини на старті, від 0 до 1 |
| `Invulnerable` | Транспортний засіб та його компоненти не отримують пошкоджень взагалі: зіткнення, кулі, вибухи |
| `ProtectCrew` | Тільки для транспортних засобів: ніхто всередині не травмується і не гине при зіткненні |
| `ClearanceWidth`, `ClearanceLength`, `ClearanceHeight` | Вільний простір (метри), необхідний у точці появи. Типове значення підходить для Ольги; збільште його для вантажівок |

### Набори (Kits)

Набір — це набір предметів для однієї команди. Поля:

| Поле | Значення |
|---|---|
| `Command`, `DisplayName` | Так само, як для пресетів |
| `MaxSpawns`, `LimitMinutes` | Ліміт на гравця |
| `RealTimeLimit` | Рахувати `LimitMinutes` у реальному часі замість ігрового (переживає перезапуск сервера) |
| `AdminOnly` | Тільки адміністратори можуть використовувати |
| `ToInventory` | Покласти предмети в інвентар гравця, де є місце; решту покласти на землю. Інакше все кладемо на землю перед ними |
| `Items` | `ClassName`, `Count` та `Contents`. Вміст кладеться всередину предмета: кріпиться туди, де підходить (магазини, глушники, батареї, кобури), інакше в його вантажний відсік, і може мати власний вміст |

Предмети з наборів створюються новими, магазини та боєкомплект повними, батареї заряджені, пляшки повні води. Магазин, зазначений у вмісті зброї, завантажений патроном у каналі ствола.

Типовий конфіг записується лише тоді, коли файлу `config.json` не існує. Після оновлення мода видаліть старий файл (або додайте нові поля в нього), щоб застосувати нові типові значення; журнал сервера попереджає, якщо файл є старою версією.

Ігровий час та історія спавну для кожного гравця зберігаються у `$profile:ChillSpawn/players/`.

## Додавання команд (розширення)

Створіть підклас `CS_ChatCommand` та зареєструйте його з іншого мода або в цьому:

```c
class MyRulesCommand : CS_ChatCommand
{
	override string GetName() { return "rules"; }

	override void Execute(PlayerBase player, array<string> args)
	{
		CS_Messenger.Send(player, "No KOS in the safe zone.");
	}
}

modded class CS_Core
{
	override protected void RegisterCommands()
	{
		super.RegisterCommands();
		Commands.Register(new MyRulesCommand());
	}
}
```

## Відомі обмеження / спочатку тестуйте

Базовий функціонал працює на DayZ 1.30 experimental. Перевіряйте це на тестовому сервері при зміні конфігурації або оновленні гри:

1. **Хук чату: працює.** Мод читає чат через `MissionServer.OnEvent` з `ChatMessageEventTypeID`, тому гравцям не потрібно нічого встановлювати. У [StarDZ DayZ Modding Wiki](https://github.com/StarDZ-Team/DayZ-Modding-Wiki) `ChatMessageEventTypeID` перелічено як клієнтську подію, але на сервері DayZ 1.30 experimental сервер також отримує її. Подія надає лише ім'я відправника, тому гравці ідентифікуються за іменем. Якщо два гравці мають одне ім'я, команда буде проігнорована.
2. **Імена класів кріплень та наборів.** Перевірте, що кожен клас у `Attachments` та кожен предмет з набору створюються (журнал сервера друкує `Could not attach …`, `Could not create …` або `Could not put …` для тих, що не працюють), і що автомобіль заводиться та їде.
3. **Захист автомобіля.** `Invulnerable` зупиняє пошкодження автомобіля та частин, з якими він був створений; частини, прикріплені пізніше, не захищені. `ProtectCrew` зупиняє пошкодження людей всередині при зіткненні. Жоден із них не захищає людей, яких влучив автомобіль. Обидва зберігаються в пам'яті, тому після перезапуску сервера автомобіль, який ще не зник, стає звичайним автомобілем.
4. **Перевірка перешкод.** Використовує `IsBoxColliding` з коробкою розміром із автомобіль, піднятою на 0,3 м над землею, плюс перевірку моря/озера. Пробує 10 напрямків на відстанях 6, 9 та 12 м. Переконайтеся, що він не помилково вважає кущі перешкодами, і що він виявляє стіни та паркані. Він не перевіряє ухил, тому автомобіль може опинитися на крутому схилі.
5. **Таймери зникнення живуть в пам'яті.** Якщо сервер перезавантажується до завершення таймера автомобіля, автомобіль залишається у світі як звичайний постійний транспортний засіб. Якщо гравець знаходиться в автомобілі, коли таймер спливає, спроба зникнення повторюється щохвилини, поки він не вийде.

## Збірка (Building)

### Linux

```bash
tools/build-linux.sh
```

Це запаковує `dist/@ChillSpawn/addons/ChillSpawn.pbo` за допомогою PBO Builder із [RaG DayZ Tools](https://github.com/Tyson89/RaG-DayZ-Tools). RaG DayZ Tools є безкоштовним програмним забезпеченням під власною ліцензією і не включається сюди: скрипт клонує його в `~/.cache/rag-dayz-tools` при першому запуску, або використовує шлях, який ви передаєте (`tools/build-linux.sh /path/to/RaG-DayZ-Tools`) або встановлюєте в `RAG_TOOLS_DIR`. Потребує `python3` версії 3.10+ та `git`.

Скрипт запускає попередні перевірки RaG та пакує скрипти як є. Він пропускає бінаризацію, конвертацію `config.cpp` та підписування, які потребують програм DayZ Tools для Windows. Серверний мод лише зі скриптами не потребує жодного з них. Нічого на Linux не компілює Enforce Script, тому помилки скриптів відображаються лише в журналі `.rpt` сервера під час запуску.

### Windows

Запакуйте папку `ChillSpawn/` у `@ChillSpawn/addons/ChillSpawn.pbo` за допомогою AddonBuilder із DayZ Tools або RaG PBO Builder. Моді лише для сервера не обов'язково потрібно підписування, але якщо сервер перевіряє підписи, підпишіть PBO та помістіть `.bikey` у папку `keys/` сервера.

## Встановлення

1. Скопіюйте папку `@ChillSpawn` у кореневу папку сервера, поруч із `DayZServer_x64.exe`.
2. Завантажте її як серверний мод:
   - **Звичайний сервер:** додайте `-servermod=@ChillSpawn` до рядка запуску.
   - **CFTools Architect:** використовуйте **Add Local Mod**, виберіть `@ChillSpawn` та встановіть тип **Server**.
3. Запустіть сервер. Він створює `profiles/ChillSpawn/config.json` та пише в лог `[ChillSpawn] Loaded … spawn presets, … kits and … admins.`
4. Додайте Steam64 ID ваших адміністраторів до `Admins` у цьому файлі та перезавантажте сервер.

**Оновлення:** повністю зупиніть сервер перед заміною `ChillSpawn.pbo`. Робочий сервер блокує файл, і швидкий перезапуск може не залишити часу для його заміни.
