# ChillSpawn

[English](README.md) · [Slovenčina](README.sk.md) · [Deutsch](README.de.md) · **Українська** · [Polski](README.pl.md) · [Français](README.fr.md) · [Español](README.es.md) · [Português](README.pt.md)

> Машинний переклад. У разі розбіжностей чинним є [англійський оригінал](README.md).

Серверний мод для DayZ. Гравці вводять `!car` у чат, щоб створити готовий до поїздки червоний «Ольга 24» за шість метрів північніше від них: з чотирма колесами, свічкою запалювання, радіатором, зарядженим акумулятором, фарами, дверима, капотом і багажником, повним баком пального, охолоджуючої рідини, мастила та гальмівної рідини. Якщо ця точка заблокована або знаходиться у воді, спроба повторюється для сусідніх точок; якщо жодна не вільна, гравця повідомляють переміститися, і ця спроба не зараховується до ліміту. Гравець отримує приватне повідомлення про те, що автомобіль зникне через 15 хвилин. Кожен гравець може створити 3 автомобілі на годину ігрового часу (час перебування в мережі, а не реальний час).

Клієнтам не потрібно встановлювати цей мод. Завантажуйте його з `-servermod=@ChillSpawn`. Написано для DayZ 1.30.

> **Статус: не перевірено.** Код написаний за допомогою Claude і ще не компілювався або не запускався на сервері. Ознайомтеся з [Відомі обмеження / спочатку протестуйте](#відомі-обмеження--спочатку-протестуйте) перед використанням на живому сервері. У файлі [docs/PROMPTING.md](docs/PROMPTING.uk.md) показано, як він був створений.

## Структура

```
ChillSpawn/                    -> packs to @ChillSpawn/addons/ChillSpawn.pbo
  config.cpp                   CfgPatches/CfgMods, script modules
  scripts/3_Game/ChillSpawn/   CS_Config (JSON config), CS_PlayerTracker (playtime + rate limit)
  scripts/4_World/ChillSpawn/  CS_Core, CS_Commands, CS_VehicleSpawner, CS_Messenger
  scripts/5_Mission/ChillSpawn/ MissionServer hooks (chat, connect, disconnect)
config.example.json            the default config, for reference
docs/PROMPTING.md              how this mod was made with Claude, and prompts to make your own

```

## Конфігурація

При першому запуску мод записує `$profile:ChillSpawn/config.json` (папка `-profiles` сервера). Кожний пресет у `Presets` стає окремою командою чату, тому власники серверів можуть додавати більше транспортних засобів або предметів без зміни коду. За замовчуванням є три:

| Команда | Створює |
|---|---|
| `!car` | Червоний Ольга 24, готовий до поїздки |
| `!ada` | Зелений Ada 4x4, готовий до поїздки (`OffroadHatchback_Blue` / `_White` для інших кольорів, з відповідними класами дверей `_Blue` / `_White`, капота та багажника) |
| `!hatchet` | Сокира на землі за 1 м |

Дві вбудовані команди завжди доступні:

| Команда | Дія |
|---|---|
| `!list` | Перелічує всі пресети по одному на рядок, показуючи, скільки створень залишилося гравцю за годину ігрового часу, і коли ліміт вичерпано — скільки часу залишилось до наступного циклу |
| `!help` | Перелічує всі команди |

Пресет не може називатися `list` або `help`; вбудовані команди мають пріоритет, а серверний лог видасте попередження.

Кожен пресет має свій ліміт (3 Ольги та 3 сокири за годину — це окремі дозволи). Щоб додати пресет, скопіюйте блок у `Presets`, надайте йому новий `Command` і перезавантажте сервер. Поля:

| Поле | Значення |
|---|---|
| `Command` | Команда чату без префікса (`car` → `!car`) |
| `DisplayName` | Ім'я, що відображається в повідомленні |
| `ClassName` | Клас транспортного засобу або предмета для створення |
| `Attachments` | Класи кріплень. Повторюйте клас для кожного слота (наприклад, чотири колеса) |
| `DistanceMetres`, `BearingDegrees` | Де з'являється об'єкт відносно гравця. 0° = північ, 90° = схід |
| `DespawnSeconds` | 0 = ніколи не зникає |
| `MaxPerPlaytimeHour` | Ліміт створень на годину ігрового часу, вважається для кожного пресета окремо |
| `SpawnMessage` | `%1` = DisplayName, `%2` = хвилин до зникнення |
| `FuelFraction`, `CoolantFraction`, `OilFraction`, `BrakeFluidFraction` | Тільки для транспортних засобів: початковий рівень рідин від 0 до 1 |
| `ClearanceWidth`, `ClearanceLength`, `ClearanceHeight` | Простір (метри), необхідний у точці створення. За замовчуванням підходить для Ольги; збільште для вантажівок |

Конфігурація за замовчуванням записується лише тоді, коли не існує файлу `config.json`. Після оновлення мода видаліть старий файл (або додайте нові поля в нього), щоб активувати нові значення за замовчуванням.

Ігровий час та історія створень для кожного гравця зберігаються у `$profile:ChillSpawn/players/`.

## Додавання команд (розширення)

Створіть підклас `CS_ChatCommand` і зареєструйте його з іншого мода або в цьому:

```c
class MyRulesCommand : CS_ChatCommand
{
	override string GetName() { return "rules"; }

	override void Execute(PlayerBase player, array<string> args)
	{
		CS_Messenger.Send(player, "No KOS in the safe zone.");
	}
}

modded class CS_Core
{
	override protected void RegisterCommands()
	{
		super.RegisterCommands();
		Commands.Register(new MyRulesCommand());
	}
}
```

## Відомі обмеження / спочатку протестуйте

Ще не компілювався і не тестувався. Перевірте ці моменти на тестовому сервері:

1. **Хук чату (найбільш ймовірний для збоїв).** Мод читає чат через `MissionServer.OnEvent` з `ChatMessageEventTypeID`, тому гравцям не потрібно нічого встановлювати. У [StarDZ DayZ Modding Wiki](https://github.com/StarDZ-Team/DayZ-Modding-Wiki) `ChatMessageEventTypeID` перелічений як подія клієнтської сторони, а їхній підручник із команд чату використовує невеликий клієнтський мод. Спочатку протестуйте це: якщо на `!help` немає відповіді, сервер не отримує події чату, і моду знадобиться частина для клієнта. Подія надає лише ім'я відправника, тому гравці визначаються за ім'ям. Якщо два гравці мають одне ім'я, команда буде проігнорована.
2. **Імена класів кріплень.** Перевірте, що кожен клас у `Attachments` правильно кріпиться (серверний лог друкуватиме `Could not attach …` для тих, що не працюють), і що автомобіль заводиться та їде.
3. **Перевірка перешкод.** Використовує `IsBoxColliding` з коробкою розміром з автомобіль, піднятою на 0.3 м над землею, плюс перевірку моря/ставу. Він пробує 10 напрямків на відстанях 6, 9 та 12 м. Перевірте, що чагарники не помилково вважаються перешкодами, і що стіни та паркани виявляються. Нахил не перевіряється, тому автомобіль може все ще опинитися на крутому схилі.
4. **Таймери зникнення живуть у пам'яті.** Якщо сервер перезавантажиться до завершення таймера автомобіля, автомобіль залишиться у світі як звичайний постійний транспортний засіб. Якщо гравець сидить в автомобілі, коли таймер закінчується, спроба зникнення повторюватиметься кожну хвилину, доки він не вийде.

## Збірка

### Linux

```bash
tools/build-linux.sh
```

Це упаковує `dist/@ChillSpawn/addons/ChillSpawn.pbo` за допомогою PBO builder з [RaG DayZ Tools](https://github.com/Tyson89/RaG-DayZ-Tools). RaG DayZ Tools є безкоштовним програмним забезпеченням під власною ліцензією і не включено сюди: скрипт клонує його в `~/.cache/rag-dayz-tools` при першому запуску, або використовує шлях, який ви передаєте (`tools/build-linux.sh /path/to/RaG-DayZ-Tools`) або встановлюєте в `RAG_TOOLS_DIR`. Потрібен `python3` версії 3.10+ та `git`.

Скрипт запускає попередні перевірки RaG і упаковує скрипти як є. Він пропускає бінаризацію, перетворення `config.cpp` та підписання, що потребує програм DayZ Tools для Windows. Серверний мод, що містить лише скрипти, не потребує жодного з них. На Linux нічого не компілює Enforce Script, тому помилки скриптів з'являються лише в журналі `.rpt` сервера під час запуску.

Скопіюйте `dist/@ChillSpawn` у папку сервера та додайте `-servermod=@ChillSpawn` до рядка запуску.

### Windows

Упакуйте папку `ChillSpawn/` в `@ChillSpawn/addons/ChillSpawn.pbo` за допомогою AddonBuilder від DayZ Tools або RaG PBO Builder. Серверні моди не обов'язково потребують підписання, але якщо сервер перевіряє підписи, підпишіть PBO та покладіть `.bikey` у папку `keys/` сервера.
