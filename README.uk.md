# ChillSpawn

[English](README.md) · [Slovenčina](README.sk.md) · [Deutsch](README.de.md) · **Українська** · [Polski](README.pl.md) · [Français](README.fr.md) · [Español](README.es.md) · [Português](README.pt.md)

> Машинний переклад. У разі розбіжностей чинним є [англійський оригінал](README.md).

Серверний мод для DayZ. Гравці пишуть `!car` у чат, щоб з’явився готовий до їзди червоний Ольга-24 за шість метрів північніше від них: з чотирма колесами, свічкою запалювання, радіатором, зарядженим акумулятором, фарами, дверима, капотом і багажником, повним баком палива, охолоджуючоєю рідиною, маслом і гальмовою рідиною. Якщо ця точка заблокована або під водою, спроба виконується для сусідніх точок; якщо жодна не є вільною, гравця повідомляють про необхідність переміститися, і ця спроба не враховується у ліміті. Вони отримують особисте повідомлення про те, що автомобіль зникне через 15 хвилин. Кожен гравець може створити один Ольга-24 кожні 15 хвилин ігрового часу (часу підключення, а не за годинником). Створені автомобілі не отримують пошкоджень, і ніхто всередині не травмується при аварії.

Гравці також можуть писати `!survive` один раз на кожні 2 реальні години для отримання невеликого набору виживальника. Адміністратори не мають обмежень і отримують `!adminkit`.

Клієнтам не потрібно встановлювати цей мод. Завантажуйте його з `-servermod=@ChillSpawn`. Написано для DayZ 1.30.

> **Статус: протестовано на DayZ 1.30 experimental.** Команди `!help`, `!list`, `!car`, `!ada` та `!hatchet` працюють на живому сервері без клієнтського мода. Адміністратори, набори, `!survive` та захист автомобілів — нові функції, які ще не протестовані. Див. [Відомі обмеження / спочатку тестування](#відомі-обмеження--спочатку-тестування). У файлі [docs/PROMPTING.md](docs/PROMPTING.uk.md) показано, як цей мод був створений.

## Структура

```
ChillSpawn/                    -> packs to @ChillSpawn/addons/ChillSpawn.pbo
  config.cpp                   CfgPatches/CfgMods, script modules
  scripts/3_Game/ChillSpawn/   CS_Config (JSON config), CS_PlayerTracker (playtime + rate limit)
  scripts/4_World/ChillSpawn/  CS_Core, CS_Commands, CS_VehicleSpawner, CS_KitSpawner,
                               CS_CarProtection, CS_Messenger
  scripts/5_Mission/ChillSpawn/ MissionServer hooks (chat, connect, disconnect)
config.example.json            the default config, for reference
docs/PROMPTING.md              how this mod was made with Claude, and prompts to make your own
tools/build-linux.sh           builds the PBO on Linux (see Building)
```

## Конфігурація

При першому запуску мод записує `$profile:ChillSpawn/config.json` (папка `-profiles` сервера). Кожний запис у `Presets` та `Kits` стає окремою командою чату, тому власники серверів можуть додавати нові без зміни коду. Стандартні значення:

| Команда | Створює | Ліміт |
|---|---|---|
| `!car` | Червоний Ольга-24, готовий до їзди, без пошкоджень, екіпаж захищений | 1 кожні 15 хв гри |
| `!ada` | Зелений Ада 4x4, те саме (`OffroadHatchback_Blue` / `_White` для інших кольорів, з відповідними класами `_Blue` / `_White` дверей, капота та багажника) | 1 кожні 15 хв гри |
| `!hatchet` | Сокира на землі за 1 м | 3 кожні 60 хв гри |
| `!survive` | У інвентар гравця: банка тушонки, повна пляшка води, таблетки для очищення, бинт та тетрациклін | 1 кожні 2 реальні години |
| `!adminkit` | Тільки для адміністраторів. На землі перед ними: рюкзак Alice, M14 з 3 повними магазинами на 20 патронів та 3 коробками .308, M4A1 з 3 повними магазинами на 60 патронів та 2 глушниками, повний бронежилет, шолом MICH з нічним баченням та батареями, камуфляжна куртка TTsKO, штани та черевики, рукавиці та мисливський ніж | немає |

Дві вбудовані команди завжди доступні:

| Команда | Дія |
|---|---|
| `!list` | Виводить все, що гравець може створити, по одному на рядок, з кількістю залишку та, коли нічого не залишилося, часом до наступного |
| `!help` | Виводить команди, доступні гравцю |

Пресет або набір не може називатися `list` або `help`; вбудовані команди мають пріоритет, а в лог сервера з’являється попередження.

### Адміністратори

Додайте Steam64 ID адміністраторів у `Admins`:

```json
"Admins": ["76561198000000000"],
```

Адміністратори не мають обмежень і можуть використовувати команди, позначені як `AdminOnly`. Інші гравці не бачать адміністративних команд у `!help` або `!list`, і нічого не станеться, якщо вони введуть одну з них.

### Пресети

Кожен пресет має свій ліміт (один Ольга-24 та один Ада кожні 15 хвилин — це окремі дозволи). Щоб додати пресет, скопіюйте блок у `Presets`, дайте йому новий `Command` та перезавантажте сервер. Поля:

| Поле | Значення |
|---|---|
| `Command` | Команда чату, без префікса (`car` → `!car`) |
| `DisplayName` | Назва, що відображається у повідомленні |
| `ClassName` | Клас транспортного засобу або предмета для створення |
| `Attachments` | Класи, що кріпляться до нього. Повторіть клас для кожного слоту, який він заповнює (чотири колеса) |
| `DistanceMetres`, `BearingDegrees` | Де з’являється відносно гравця. 0° = північ, 90° = схід |
| `DespawnSeconds` | 0 = ніколи не зникає |
| `MaxSpawns`, `LimitMinutes` | Кожен гравець може створити це `MaxSpawns` разів кожні `LimitMinutes` хвилин ігрового часу |
| `AdminOnly` | Тільки адміністратори можуть використовувати |
| `SpawnMessage` | `%1` = DisplayName, `%2` = хвилин до зникнення |
| `FuelFraction`, `CoolantFraction`, `OilFraction`, `BrakeFluidFraction` | Тільки для транспортних засобів: наскільки повними починаються рідини, від 0 до 1 |
| `Invulnerable` | Він та його кріплення не отримують жодних пошкоджень: аварії, кулі, вибухи |
| `ProtectCrew` | Тільки для транспортних засобів: ніхто всередині не травмується і не гине при аварії |
| `ClearanceWidth`, `ClearanceLength`, `ClearanceHeight` | Вільний простір (метри), необхідний у точці створення. За замовчуванням підходить для Ольги; збільште для вантажівок |

### Набори

Набір — це набір предметів для однієї команди. Поля:

| Поле | Значення |
|---|---|
| `Command`, `DisplayName` | Як у пресетах |
| `MaxSpawns`, `LimitMinutes` | Ліміт на гравця |
| `RealTimeLimit` | Рахувати `LimitMinutes` за реальним часом, а не ігровим (переживає перезавантаження) |
| `AdminOnly` | Тільки адміністратори можуть використовувати |
| `ToInventory` | Помістити предмети в інвентар гравця туди, де є місце; решту покласти на землю. Інакше все кладемо на землю перед ними |
| `Items` | `ClassName`, `Count` та `Contents`. Вміст поміщається всередину предмета: кріпиться туди, де він підходить (магазини, глушники, батареї, кобури), інакше в його вантажний відсік, і може мати власний вміст |

Предмети наборів створюються новими, магазини та патрони повними, батареї зарядженими, пляшки повні водою. Магазин, зазначений у вмісті зброї, заряджений одним патроном у патроннику.

Стандартний конфіг записується лише тоді, коли файлу `config.json` не існує. Після оновлення мода видаліть старий файл (або додайте нові поля в нього), щоб використати нові стандартні значення; лог сервера попередить, якщо файл із старої версії.

Ігровий час та історія створень для кожного гравця зберігаються в `$profile:ChillSpawn/players/`.

## Додавання команд (розширення)

Створіть підклас `CS_ChatCommand` та зареєструйте його з іншого мода або в цьому:

```c
class MyRulesCommand : CS_ChatCommand
{
	override string GetName() { return "rules"; }

	override void Execute(PlayerBase player, array<string> args)
	{
		CS_Messenger.Send(player, "No KOS in the safe zone.");
	}
}

modded class CS_Core
{
	override protected void RegisterCommands()
	{
		super.RegisterCommands();
		Commands.Register(new MyRulesCommand());
	}
}
```

## Відомі обмеження / спочатку тестування

Базові функції працюють на DayZ 1.30 experimental. Перевірте наступне на тестовому сервері при зміні конфігурації або оновленні гри:

1. **Хук чату: працює.** Мод читає чат через `MissionServer.OnEvent` з `ChatMessageEventTypeID`, тому гравцям не потрібно нічого встановлювати. У [StarDZ DayZ Modding Wiki](https://github.com/StarDZ-Team/DayZ-Modding-Wiki) `ChatMessageEventTypeID` перелічено як клієнтський захід, але на сервері DayZ 1.30 experimental він також отримується сервером. Захід надає лише ім’я відправника, тому гравці зіставляються за іменем. Якщо два гравці мають однакове ім’я, команда ігнорується.
2. **Імена класів кріплень та наборів.** Перевірте, що кожен клас у `Attachments` та кожен предмет набору створюється (лог сервера виводить `Could not attach …`, `Could not create …` або `Could not put …` для будь-яких, які не спрацювали), і що автомобіль заводиться та їде.
3. **Захист автомобіля (нове).** `Invulnerable` зупиняє пошкодження автомобіля та деталей, з якими він був створений; деталі, встановлені пізніше, не захищені. `ProtectCrew` зупиняє ушкодження від аварії для людей всередині. Жоден із них не захищає людей, яких врізається автомобіль. Обидва зберігаються в пам’яті, тому після перезавантаження сервера автомобіль, який ще не зник, стає звичайним автомобілем.
4. **Перевірка перешкод.** Використовує `IsBoxColliding` з коробкою розміром із автомобіль, піднятою на 0.3 м над землею, плюс перевірку моря/ставки. Вона пробує 10 напрямків на відстанях 6, 9 та 12 м. Переконайтеся, що вона неправильно не вважає кущі перешкодами і що вона ловить стіни та паркані. Вона не перевіряє ухил, тому автомобіль може опинитися на крутому схилі.
5. **Таймери зникнення живуть у пам’яті.** Якщо сервер перезавантажується до завершення таймера автомобіля, автомобіль залишається у світі як звичайний постійний транспорт. Якщо гравець перебуває в автомобілі, коли таймер закінчується, спроба зникнення повторюється щохвилини, поки він не вийде.

## Збірка

### Linux

```bash
tools/build-linux.sh
```

Це пакує `dist/@ChillSpawn/addons/ChillSpawn.pbo` із PBO builder від [RaG DayZ Tools](https://github.com/Tyson89/RaG-DayZ-Tools). RaG DayZ Tools є безкоштовним програмним забезпеченням під власною ліцензією і не включено сюди: скрипт клонує його в `~/.cache/rag-dayz-tools` при першому запуску або використовує шлях, який ви передаєте (`tools/build-linux.sh /path/to/RaG-DayZ-Tools`) або задали в `RAG_TOOLS_DIR`. Потрібен `python3` 3.10+ та `git`.

Скрипт запускає попередні перевірки RaG і пакує скрипти як є. Він пропускає бінаризацію, перетворення `config.cpp` та підписання, що вимагає програм Windows DayZ Tools. Серверний мод лише зі скриптами не потребує жодного з них. Нічого на Linux не компілює Enforce Script, тому помилки скриптів з’являються лише в лозі `.rpt` сервера при запуску.

Скопіюйте `dist/@ChillSpawn` у папку сервера та додайте `-servermod=@ChillSpawn` до рядка запуску.

### Windows

Пакуйте папку `ChillSpawn/` в `@ChillSpawn/addons/ChillSpawn.pbo` за допомогою AddonBuilder від DayZ Tools або RaG PBO Builder. Моді лише для сервера не обов’язково потрібне підписання, але якщо сервер перевіряє підписи, підпишіть PBO та покладіть `.bikey` у папку `keys/` сервера.
